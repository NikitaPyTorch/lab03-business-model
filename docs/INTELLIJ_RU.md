# Как открыть и проверить готовую лабораторную в IntelliJ IDEA

В папке проекта уже есть `pom.xml`, исходники и тесты. Нужно открыть этот существующий проект. Здесь описаны действия для самостоятельного выполнения в IntelliJ IDEA; инструкция не является подтверждением, что проект уже открыт в интерфейсе или тесты уже запущены.

На данном компьютере проект расположен здесь:

```text
C:/Users/user/Documents/Codex/2026-10-08/https-youtu-be-cwt4pex-v-o/outputs/lab03-business-model
```

Если проект скачан из GitHub в другую папку, используйте её. Ориентир - находящийся внутри файл `pom.xml`.

## 1. Открыть существующий pom.xml

1. Запустите IntelliJ IDEA.
2. На стартовом экране нажмите **Open**. Если открыт другой проект, выберите **File -> Open**.
3. Перейдите в папку `lab03-business-model` и выберите **pom.xml**.
4. Нажмите **Open**. Если предложены варианты **Open as Project** и **Open as File**, выберите **Open as Project**.
5. Если IDE спросит о доверии этому проекту, выберите **Trust Project**.
6. Дождитесь импорта и индексации. В окне **Project** должны появиться `pom.xml`, `src/main/java` и `src/test/java`.

Открытие `pom.xml` как проекта позволяет IntelliJ IDEA распознать Maven-конфигурацию и загрузить структуру и зависимости. См. [официальное описание импорта проектов](https://www.jetbrains.com/help/idea/import-project-or-module-wizard.html) и [открытия Maven-проекта через pom.xml](https://blog.jetbrains.com/idea/2021/07/using-maven-in-intellij-idea/).

## 2. Выбрать JDK 25

В `pom.xml` задано `<maven.compiler.release>25</maven.compiler.release>`. Нужен JDK 25, а не только среда выполнения JRE.

На данном компьютере установлен Microsoft OpenJDK **25.0.4.1**:

```text
C:/Users/user/.jdks/ms-25.0.4.1
```

1. Откройте **File -> Project Structure** (`Ctrl+Alt+Shift+S`).
2. В разделе **Project** найдите поле **SDK** или **Project SDK**.
3. Выберите установленный JDK 25. Если его нет в списке, нажмите **Add SDK -> JDK** или **Add JDK from Disk** и укажите папку выше. Выбирается корень JDK, в котором есть `bin`, а не сама папка `bin`.
4. Для **Language level** выберите **SDK default** или уровень **25**, без включения preview-возможностей.
5. В разделе **Modules -> Dependencies** убедитесь, что **Module SDK** использует **Project SDK**.
6. Нажмите **Apply**, затем **OK**.

Названия пунктов могут немного отличаться в версиях IDEA. Настройки Project SDK и JDK для запуска Maven описаны в [документации IntelliJ IDEA](https://www.jetbrains.com/help/idea/maven-support.html).

## 3. Проверить Maven и загрузить зависимости

Для работы через IntelliJ IDEA подходит **Bundled Maven**. Отдельно устанавливать Maven не требуется; команда `mvn` в обычном терминале при этом может быть недоступна. См. [документацию JetBrains о встроенном Maven](https://blog.jetbrains.com/idea/2021/07/using-maven-in-intellij-idea/).

1. Откройте **File -> Settings** (`Ctrl+Alt+S`).
2. Найдите настройки **Maven** через строку поиска. Обычно они находятся в **Build, Execution, Deployment -> Build Tools -> Maven**.
3. В поле **Maven home path** выберите **Bundled (Maven 3)** или аналогичный вариант встроенного Maven.
4. В **Maven -> Runner** для **JRE** выберите **Project JDK** или установленный JDK 25.
5. В **Maven -> Importing** для **JDK for importer**, если это поле доступно, также выберите JDK 25.
6. Нажмите **Apply -> OK**.
7. Откройте **View -> Tool Windows -> Maven**. Нажмите **Reload All Maven Projects** / **Reimport All Maven Projects** - кнопку синхронизации на панели окна Maven.
8. Дождитесь завершения загрузки. Для первой загрузки зависимостей нужен интернет. Классы JUnit в тестах должны распознаваться.

Если появляется уведомление **Load Maven Changes**, нажмите его. Если Maven-окно пустое, нажмите в нём **Add Maven Project** и выберите существующий `pom.xml`. Кнопки импорта и синхронизации описаны в [справке окна Maven](https://www.jetbrains.com/help/idea/maven-projects-tool-window.html).

## 4. Запустить Application.main()

1. В окне **Project** откройте `src/main/java/by/bseu/pp/lab03/Application.java`.
2. Нажмите зелёный треугольник слева от `main()` или имени класса.
3. Выберите **Run 'Application.main()'**.
4. Посмотрите вывод в окне **Run**. Ожидаемый результат для данных исходного примера:

```text
Order total: 2490.0
Order status: PAID
```

В примере заказаны два ноутбука по `1200.0` и три мыши по `30.0`: `2 * 1200 + 3 * 30 = 2490`. Заказ подтверждён, платёж отмечен успешным, затем принят через `order.pay(payment)`. Поэтому итоговый статус - `PAID`, то есть «оплачен».

Для успешного завершения программа должна закончиться без исключений. Этот запуск показывает один сценарий; следующим шагом запускается полный набор тестов.

## 5. Запустить все 76 тестов

1. В окне **Project** раскройте `src/test/java`.
2. Найдите пакет **by.bseu.pp.lab03.model**, содержащий шесть классов тестов.
3. Нажмите на пакет правой кнопкой мыши.
4. Выберите **Run Tests in 'by.bseu.pp.lab03.model'**. Альтернатива: выделите папку `src/test/java` и нажмите `Ctrl+Shift+F10`.
5. Дождитесь окончания. В окне **Run** проверьте, что выполнены **76 тестов**, нет ошибок, провалов и пропущенных тестов.

IDEA умеет запускать все тесты выбранной папки или пакета; см. [официальную инструкцию Run tests](https://www.jetbrains.com/help/idea/performing-tests.html).

Состав полного набора:

| Набор | Количество |
| --- | ---: |
| `CustomerTest` | 17 |
| `ProductTest` | 14 |
| `OrderItemTest` | 5 |
| `PaymentTest` | 10 |
| `OrderTest` | 23 |
| `StructureTest` | 7 |
| **Всего** | **76** |

Другой способ проверки: в окне **Maven** раскройте **lab03-business-model -> Lifecycle** и дважды нажмите **test**. Для успешного полного запуска ожидаются `Tests run: 76`, `Failures: 0`, `Errors: 0`, `Skipped: 0` и `BUILD SUCCESS`. Это ориентиры для проверки, а не утверждение об уже выполненном запуске.

Если тест красный, откройте сообщение: сравните ожидаемое и фактическое значение либо тип исключения. Исправляется основной код, а не предоставленный тест.

## 6. Открыть историю Git

1. Откройте **View -> Tool Windows -> Git** (`Alt+9`).
2. Выберите вкладку **Log**.
3. Выберите коммит с реализацией и посмотрите список изменённых файлов и разницу версий.
4. Для защиты объясните, какие классы реализованы в коммитах. Предоставленные файлы `src/test/java` должны оставаться исходными.

Просмотр истории во вкладке Log описан в [документации JetBrains](https://www.jetbrains.com/help/idea/investigate-changes.html).

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `release version 25 not supported` | Project SDK и Maven Runner используют JDK 25; после исправления выполнен Reload Maven. |
| Красные `org.junit.jupiter` или неизвестная аннотация `@Test` | Завершён импорт Maven; есть интернет для загрузки зависимостей; Maven не работает в Offline Mode. |
| Не видны `src/main/java` и тесты как часть проекта | Открыт корневой `pom.xml` как проект, а не отдельно файл Java. |
| Вместо 76 тестов выполнено меньше | Запущен весь пакет или `src/test/java`, а не один Test-класс или метод. |
| `mvn` не найден в терминале | Для действий выше используйте окно Maven в IDEA со встроенным Maven. |
| Не видно окна Maven, Git или Run | Найдите его через **View -> Tool Windows**. Действие можно найти через `Ctrl+Shift+A`. |
